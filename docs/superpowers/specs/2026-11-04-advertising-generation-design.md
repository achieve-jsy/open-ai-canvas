# C：广告镜头生成、逐镜头旁白与成片交付

状态：待用户审阅的书面规格，尚未批准实施。基线 e96fe3d2，B已交付需求/分镜/确认历史并完成Chrome核心流程验收。本文不代表已支持模型生成或已产出真实商品广告。

## 1. 目标与已确认约束

面向诚实归因的开源二次开发面试演示，完成：选定已确认脚本 → 逐镜头生成视频及TTS → 人工试听/预览并采用 → 组装现有时间线 → 导出可播放MP4。沿用中文、单商品、3–5镜头、15–30秒、1080×1920。

用户已确认：C包含逐镜头TTS，全片默认统一音色，空旁白不生成；背景音乐先手动上传。每次实际生成明确确认费用；失败不自动再次收费。旁白长于镜头时阻止组装，提示缩短文案或调整脚本并重新确认；不自动截断、加速、延长广告。

首版不做AI改写脚本、自动导演、声音克隆、品牌档案、多比例、变体、自动选优或自动批量重试。B的确认内容保持不可变。脚本不合适时返回B编辑并确认新版本，不在生成面板偷偷修改提示词或旁白。

## 2. 方案比较与复用依据

推荐：广告薄业务层维护确认版本、生成授权、候选采用及组装来源；执行复用既有Task、资源存储、账务和FFmpeg时间线。

- 不选仅在前端串联任务：刷新恢复、重复收费、跨版本采用和资源保护无法可靠约束。
- 不选新建通用工作流引擎：重复队列、模型协议、计费和媒体存储。
- 不直接复用CreationRun整套画布审批：其媒体准入绑定画布节点/方案操作，当前prepareCreationTask还排除audio。只提取确有重复的任务准备/报价签名/事务入队能力，不让广告伪装为Agent或短剧。

已读落点：

- [任务准入](../../../backend/internal/app/task_creation.go)：服务端目录解析、权限/配额、计费、持久化。
- [既有报价批准执行](../../../backend/internal/app/creation.go)：准备不入队、报价重验、事务创建任务和订单的模式；需抽取小型共享实现，不能直接调用其画布限定流程。
- [音频执行](../../../backend/internal/app/provider_audio.go)：同步speech与异步audio任务。
- [媒体探测](../../../backend/internal/app/media_probe.go)：复用probeMediaFile，未知时长不当成0秒合格。
- [时间线合同](../../../web/src/types/timeline.ts)、[渲染入口](../../../backend/internal/app/task_timeline.go)、[FFmpeg计划](../../../backend/internal/app/timeline_render_plan.go)：音视频、文字、Logo及输出参数；不另建编辑器。

## 3. 用户流程与页面边界

在广告详情增加“制作成片”区，进入时明确选择某个已确认版本。显示来源修订、总时长、当前草稿是否已不同；新确认不会自动切换正在制作的版本。一个确认版本对应一个制作记录。

每镜头展示冻结画面描述、参考图、旁白、屏幕文字、目标时长；分列视频候选和旁白候选。状态取自真实Task：等待、执行、成功、失败、取消；媒体已生成但保存失败不能显示为可采用。任务完成不依赖页面常驻。关闭页面不代表取消任务，取消后费用以账务终态为准。

操作：选择模型/音色 → 获取报价 → 确认费用并提交一个任务 → 预览/试听 → 明确采用。视频与旁白独立，每次只生成一个候选；暂不提供“一键全部生成”。失败显示原因与原任务/订单，重新生成必须新报价、新确认。响应丢失则查询原提交，不创建新任务。

同一制作记录提供全片默认TTS模型及音色。改默认值只影响未来报价；已采用不同音色时展示逐镜头实际音色，不宣称已统一，不自动付费重生成。语速首版固定1。

保留已有候选与历史成片，生成新候选不覆盖已采用项。生产状态使用独立revision，与B草稿revision分开；采用、音乐设置等更新返回409时保留本地选择并刷新对照，不最后写入覆盖。

## 4. 模型与输入约束

首版仅接入服务端受管目录中当前用户可见、可执行、可报价的视频和TTS模型；不接浏览器自定义密钥、工作流插件、Agent运行时或隐藏模型。无可用模型明确提示管理员配置，不假装成功。模型/路由/价格由服务端重新解析。

视频提示词由固定版本模板根据冻结商品需求与镜头visual构建，并在报价前展示完整最终提示词。禁止生成文字的默认提示不能代替字幕轨道。参考图来自该镜头冻结referenceResourceIds中的图片，按原顺序；没有显式图片引用时使用第一张冻结商品图。首版不把视频或音频参考发给供应商；有此类镜头引用时给出不支持提示，要求调整脚本，不能静默丢弃。

按能力目录校验参考图数量、9:16、分辨率与可选时长。目标镜头时长不在模型档位时，报价前明确展示所选不短于目标的最小支持时长与费用；不存在合适档位则禁止提交。生成分辨率不必原生1080×1920，但必须说明最终会缩放，不冒充原生高清。

TTS输入严格为冻结voiceover，选合法音色及输出格式；空白旁白无任务。拒绝客户端任意提示词、外部URL、原始provider配置、费用、归属或产物ID注入。所有音视频来源使用当前用户可读Resource，不持久化签名URL。

## 5. 持久化：最少业务状态

新增四张小表；不新建镜头模型、候选文件表或账务表。第四张只保存渲染尝试的持久幂等映射，避免把最后一个taskId误当作全部重放记录。精确DDL及下一schema版本在实施计划核对当前版本后确定，沿用户批准的原生版本化GORM迁移，不引入Atlas或修改已发布checksum。同步SQLite/PostgreSQL与搬迁清单。

1. advertising_productions：ID、projectId、confirmedRevisionId（同项目且唯一）、revision、settingsJson、timestamps。settings包含默认TTS选择、按shotId的已采用submissionId及视频裁剪起点、可选音乐Resource与音量。内容严格按冻结shotId验证，不接受任意JSON键。
2. advertising_submissions：ID、productionId、shotId、kind(video/audio)、clientOperationId、requestHash、无密钥的规范化requestJson、quoteJson、priceSignature、expiresAt、approvedAt、可空taskId及timestamps。unique(productionId,clientOperationId)，taskId唯一。Task及其ResultJSON是任务状态/产物的真相；一提交只允许一个产物，不另造候选状态机。
3. advertising_assemblies：ID、productionId、clientOperationId、sourceProductionRevision、selectionHash、timelineJson、可空canvasId、timestamps。unique(productionId,clientOperationId)。组装输入不可变；人工后改画布不反写这份快照。
4. advertising_render_attempts：ID、assemblyId、clientOperationId、taskId、createdAt。unique(assemblyId,clientOperationId)，taskId唯一；任务创建与尝试插入同事务。旧请求即使在新尝试以后重放也返回自己的Task，不重复渲染。状态/结果仍只读取Task。

父子归属用约束与服务事务共同验证。外键清理顺序、Task/Canvas保留后的空关联在迁移测试覆盖。advertising_resource_references复用scopeKey增加production:<id>、candidate:<submissionId>、assembly:<id>范围；待生成输入已有确认版本引用，成功产物和音乐在对应业务事务增加保护。

被广告提交或渲染尝试引用的Task不得由通用历史清理删除（用户可取消，不能抹掉关联任务）；删除整个广告后解除这类业务保护，既有账务留存规则仍有效。

首版不单独删除候选：保留所有已存储候选，避免采用/取消采用造成意外数据丢失；列表分页20，最大100，不无界返回。新增业务占用进入普通删除、彻底删除、管理员删除与孤儿清理的共同引用查询。任务终态写入产物和candidate引用需原子完成，不能仅靠“读详情时补引用”。

## 6. 费用批准、幂等与竞争

准备阶段不入队、不调用模型、不扣费：服务端从确认内容构建任务，复用现有目录/计价能力，持久化报价和规范请求。报价有效期5分钟，显示模型、生成时长或计价数量、预授权积分、是否估算以及取消/失败不保证零费用。

确认提交携带submissionId和展示过的quoteHash。事务内核验用户/广告/确认版本、报价未过期、当前权限/可用性/价格签名、库存/额度；价格或影响费用的参数变化返回409，要求重新报价确认，不能自动接受涨价或更换模型。免费报价也需确认。

同一提交的Task、订单预授权及taskId回写原子提交。并发或重放返回同一个Task；同一clientOperationId不同请求返回409。先查已执行提交，再判断报价过期，保证成功后重放不会再收费。客户端断线不自动换幂等键；刷新可查询提交列表恢复。

复用Task/订单的授权上限与结算规则；如现有某计价模式无法约束到用户批准的上限，首版明确禁用该模式，不能只在UI展示估价却允许无限实收。供应商账单差异不得静默追加用户扣款。对广告任务关闭会导致第二次生成的自动重试/路由重发；状态轮询及已知provider request ID恢复不等于新生成，按既有安全机制执行。

公共任务创建/重试不得绕过广告提交费用批准：受管广告Task只能由广告提交入口建立，通用重试返回明确指引。普通画布任务不能伪造广告来源并成为候选。任务中心可查看/取消；任务来源由服务端绑定，不信任metadata标签。

任务入队与广告删除继续共享事务生命周期保护。删除先提交则不得入队/扣费；入队先提交则活动任务阻止删除。完成回写采用同样顺序，禁止删除后“复活”候选引用。账务/审计记录不随广告删除；独立媒体保留，画布解绑而非删除。

## 7. 采用、真实时长与组装规则

采用只允许同用户、同production、同shot、同kind的成功提交产物；资源必须已落库且可读取。供应商返回其他版本/镜头或前端随意传resourceId均拒绝。采用用CAS，创建候选不自动改变选择。新脚本确认版本不自动继承旧候选。

服务端复用probeMediaFile检查真实文件，不能只信客户端width/durationMs或上游标称时长。探测不可用、时长未知或媒体损坏时可保留候选供诊断，但不能组装/导出。远端资源经现有读取与受限临时文件流程处理，超时/体积限制及清理照旧。

- 视频必须每镜头有一条采用项。默认裁剪起点0，允许人工选择非负毫秒起点；源片从起点剩余时长必须覆盖整个镜头。较长视频按预览中明确显示的区间裁剪，较短视频阻止组装，不使用渲染器末帧填充掩盖不足。
- 非空旁白必须采用一条TTS。实际旁白时长不得超过镜头时长，严格按探测毫秒比较；短旁白从镜头起点播放，剩余自然静音。超时只能缩短文案/调整镜头并确认新版本，或另行明确报价生成新候选。
- 原视频声音默认静音，避免与TTS冲突；旁白音量1，背景音乐默认0.15，可调0–1，0表示静音。音乐长于广告则裁至结束，短于广告不循环，后段静音；先试听，不自动ducking。
- 音乐首版最多1个，接受B附加资源池已有的音频或通过现有上传新绑定的音频，使用相同音频MIME限制；所有权与ready状态强校验。源原声固定关闭，首版不提供开启选项。
- 字幕首版使用冻结onScreenText，按镜头区间展示，不伪称逐字语音对齐。旁白不自动复制成第二套字幕；不依赖Whisper。Logo有则复用图层，无则不生成。
- 1080×1920输出；默认pad避免裁掉商品，用户可在组装预览显式选择crop。镜头顺序及总时长严格遵循确认版本，不能用空白/黑屏填缺镜头后标为广告完成。

## 8. 时间线与渲染交接

组装前服务端再次校验制作revision、所有选择、引用可读性和真实时长，生成标准TimelineProject v2及selectionHash。一个新组装创建一份新的已保存CanvasProject，带现有时间线；不覆盖任何用户正在编辑的画布。同幂等键相同输入返回原组装及画布，不重复创建。

视频轨、逐镜头旁白轨、可选音乐轨、文字轨和Logo图层使用现有directMedia/Resource与渲染快照合同。必要的媒体Asset通过已有资源到素材入口建立；不得复制媒体字节或伪造assetId。画布标题包含广告名/来源版本，支持打开原有时间线编辑器。

广告面板“导出此组装”渲染不可变assembly.timelineJson，复用现有TimelineRenderTask/worker；关联任务与组装原子、幂等。渲染不调用模型，现有本地渲染若无用户积分费用须如实说明，不等同无服务器成本。失败保留组装和输入，用户明确重试产生新的渲染尝试，不覆盖旧成功产物。

在时间线编辑器修改后导出属于手动编辑版，由现有任务中心管理；不得在广告面板把它标作原assembly的确定性重放。广告面板明确分开“导出原组装”和“打开时间线继续编辑”，两者不偷偷双向同步。

MP4只有在任务成功、资源可读取、媒体探测通过后显示“成片可下载”。同时显示来源确认、选择的候选与导出任务。编码总时长允许一帧误差（30fps≤34ms），不允许缺音轨或以黑测试片冒充成片。

## 9. API与边界

全部位于登录鉴权的/ad-projects/:id下，不依赖短剧开关。沿现有http信封、AbortSignal及用户scope缓存。拟定端点：

- POST /productions：confirmedRevisionId，重复返回该版本的制作记录；GET /productions/:productionId返回设置与采用状态。
- PATCH /productions/:productionId：expectedRevision及完整受限settings；保存采用前服务端验证，禁止直接改报价/任务字段。
- GET /productions/:productionId/submissions：分页历史；POST同路径：shotId、kind、受限模型选择、clientOperationId，返回报价。
- POST /productions/:productionId/submissions/:submissionId/execute：quoteHash，显式批准并提交；刷新报价用新提交，不复用已批准内容。
- POST /productions/:productionId/assemblies：expectedRevision、clientOperationId、fit；GET /assemblies及/:assemblyId读取来源、画布和导出状态。
- POST /productions/:productionId/assemblies/:assemblyId/renders：clientOperationId，幂等创建渲染尝试；GET同路径分页查询全部尝试，按advertising_render_attempts关联Task。

写正文≤256KiB，沿B严格JSON规则；分页最大100。clientOperationId为UUID；模型/音色ID最大120字符并校验目录；所有revision为正整数。媒体不走JSON正文。跨用户对象404，文档/能力错误400，CAS/报价过期/来源不匹配409，配额/鉴权保持统一原因码；新增原因码与OpenAPI/TS同步。

## 10. 实施与验收边界

实施计划按持久化/授权→视频与TTS任务→候选与资源保护→组装渲染→真实页面→整体回归顺序拆分，不在规格批准前写产品代码。对修改的共用准入/计费逻辑必须检查全部调用方并保留现有Creation/Agent回归。

必须留下可运行检查：

1. SQLite新库/升级/重复迁移、约束、搬迁顺序；专用PG配置后执行同等事务/竞态用例，未配置明确跳过。
2. 同提交并发只产生一个任务和一笔预授权；响应丢失重放；过期/涨价/越权/被删广告零新增任务和订单；通用任务/重试旁路拒绝。
3. 旧版本候选不得跨版本采用；后台完成刷新恢复；资源丢失、引用删除、完成与删除竞态、事务失败回滚。
4. TTS超时、未知时长、短视频、非完整采用阻止组装；短旁白尾段静音；源视频静音、音乐音量0、字幕与Logo保留。
5. 重复组装不重复画布，重新组装不覆盖手动编辑；重复导出不重复任务；旧产物仍可访问。
6. 真React交互及浏览器：报价确认、失败保留、恢复、试听采用、组装、跳转时间线、成片下载、明暗/窄屏/键盘。
7. 本地确定性媒体通过真实FFmpeg输出15–30秒竖屏、非黑画面、字幕/Logo/旁白/音乐的MP4并用ffprobe核验。
8. 真供应商验收独立列出：选具体受管视频/TTS模型、明确单次/累计预算后才调用。预录媒体或fake provider仅为合同测试，不能标“真实AI广告已验收”。

当前仍无真实供应商验收授权、模型选择或预算。开发测试默认零付费；不会把本规格批准解释为不限额调用授权。PostgreSQL/Redis/OSS验收继续独立报告。
