## 当前交付边界

广告入口是登录后的“广告项目”，路由为 `/ad-projects` 与 `/ad-projects/:id`，不依赖短剧开关。B阶段只做中文、单商品、15–30秒、1080×1920竖屏广告的需求与手工分镜：**已确认脚本不等于广告已生成**。

不调用模型、不创建镜头生成任务、不扣费，也不输出MP4。A阶段合成测试片不是成品广告证据。后续C/D才设计基于确认版本的生成、候选采用与时间线，不在B预建这些实体。

## 使用流程

1. 新建项目并输入项目名；草稿允许暂时不完整。
2. 填写商品、受众、卖点、CTA、目标秒数和可选品牌信息。
3. 从已有远程素材库或上传绑定商品图、Logo、附加素材。商品与Logo只接受PNG/JPEG/WebP；附加素材接受这些图片及MP4、MP3、M4A、WAV。
4. 添加镜头并使用上移/下移调整顺序。每个镜头有稳定UUID、时长、画面、旁白、屏幕文字及资源池内的参考素材。
5. 明确点击“保存草稿”。只有收到服务端成功响应才显示已保存；上传只落本地时提示“仅本地，尚未可绑定”，不会将本地键冒充Resource ID。
6. 没有本地改动时点击“确认脚本”，再次确认后冻结版本。确认要求3–5镜头、合计等于目标时长，以及商品图、商品名、受众、CTA和至少一条卖点。
7. 确认历史只读；编辑当前草稿不会改变历史。已保存草稿与最新确认不同会单独提示。离开脏页面或上传中页面会提示风险。

## 保存、确认与冲突

草稿有独立递增revision，与通用Project revision不同。保存、确认、删除均携带expectedRevision。保存事务原子更新项目名、完整草稿与当前引用；过期写入返回409，不做最后写入覆盖。UI保留本地输入并展示服务端内容对照；用户可放弃本地，或明确保留本地并基于最新revision重新保存。

确认记录sourceRevision是被确认的草稿revision，不是下次写入令牌。同一sourceRevision重试返回同一确认ID，不将latest指针倒退；当前内容与latest完全一致时再次确认不制造版本。客户端确认后重新读取当前草稿，避免将旧确认快照配上较新的currentRevision。网络失败不自动重发写请求；保留输入，允许用户主动重试或刷新核对。

## 资源与任务生命周期

草稿和每份确认版本分别拥有去重引用。仍被镜头引用的资源不能从整个资源池移除，需先明确取消镜头引用；移除当前草稿引用不删除历史引用。快照冻结服务端资源ID、稳定标题（当前Resource无独立标题时回退ID）、MIME、尺寸、时长，不冻结签名URL。

普通素材删除返回占用来源；彻底删除入口、孤儿清理与失败公告上传清理同样保留广告依赖。删除广告只删除广告内容并解绑画布，不删除独立媒体；活动任务阻止删除。

广告项目ID保留 `ad_` 命名空间，避免已删除的服务端广告被任务入口当成从未同步的本地画布。免费/付费/重试入队均在事务内、计费前检查广告归属与存在性；PostgreSQL任务表写锁与低频删除排他锁配对。其他任意本地画布ID仍保留原语义。该命名空间适用于本次尚未发布的新实体，不引入历史数据兼容层。

## 数据与迁移

沿用仓库原生GORM版本化迁移，新增schema79：advertising_projects、advertising_revisions、advertising_resource_references。确认版本唯一键为(project_id, source_revision)，资源引用使用RESTRICT外键；latest由事务维护，避免循环外键。历史迁移校验记录不改写。SQLite到PostgreSQL搬迁顺序包含三表。

在专用测试环境或完成备份后，沿部署原有配置运行migrate-schema up/status/verify。开发检查必须显式指定隔离CANVAS_BACKEND_DATA_DIR，不能使用backend/data。本次执行临时SQLite的up→status→verify→up；旧库升级、约束及重复执行由测试覆盖。

PostgreSQL测试需专用CANVAS_TEST_POSTGRES_DSN，使用随机schema；未配置时跳过，不能算通过。搬迁测试以SQLite两端验证搬迁逻辑，不冒充真实PostgreSQL验证。

- 自动覆盖：草稿校验/CAS、不可变历史/确认幂等、跨用户访问、资源保护、短剧旁路、8条鉴权HTTP接口及严格JSON。
- 真实React DOM测试：空稿保存、镜头重排、秒/毫秒转换、未保存禁止确认、失败保留输入、409对照、确认重试、刷新恢复、后台refetch不覆盖编辑、账号/项目切换、本地上传降级与显式解除引用。
- 前端全量测试、typecheck、lint、生产build，以及后端database/repository/handler/搬迁工具与范围app回归通过。最终评审修复另行复跑。
- 临时SQLite迁移CLI通过；未执行真实PostgreSQL、Redis多实例、OSS故障注入和完整Agent运行时。
- 已在隔离SQLite与真实Vite应用上完成Chrome无头浏览器验收：首次注册登录、创建广告、实际PNG上传、3镜头共15秒、保存、确认、刷新恢复、已保存新稿不改变旧确认、显式解除镜头引用。主流程由真实表单操作；共享资源及仅历史引用的删除保护另以浏览器同源HTTP调用验证，不冒充素材库删除UI验收。
- 已检查1440px明暗截图、390px窄屏截图（无横向溢出）和Tab到保存按钮的可见焦点。并非完整辅助技术或所有断点验收。测试后关闭后端、Vite与隔离Chrome，不改现有账号数据、不调用付费模型。
