# 广告生成与成片

这是独立广告项目的C阶段，不是短剧自动编排，也不是一次点击即可发布的广告。基于已有影策任务、账务、资源、画布和FFmpeg能力增加确认版本制作流程；生成质量仍由模型与人工审核决定。

## 脚本规划（制作前）

广告草稿可选用后端视觉文字模型规划：必须是15秒目标、恰好一张归属当前用户的已就绪商品图片；图片最大8MiB。服务器从`CANVAS_AD_SCRIPT_CHANNEL_ID`与`CANVAS_AD_SCRIPT_MODEL_KEY`选定启用的系统模型，必须声明文字看图能力；未配置则拒绝。单次最多35秒、输出1200 token，单账号每日3次、全局每日200次，账号及项目同时只能有一次运行调用。规划由运营方承担，不创建Task、用户报价或用户积分记录，不改变下面逐镜头视频和旁白的费用审批。

页面以操作UUID与草稿revision提交；刷新后可读取最新规划或指定操作UUID。旧操作键始终恢复同一结果，45秒仍未完成的操作转为失败，新尝试必须换键并重新计入限额。返回的ready候选仍要人工核验并经现有草稿CAS保存；项目或资源变更时不得直接采用。仅允许模型输出三段视觉场景，不采纳模型生成的事实、CTA、旁白与屏幕文案；这些字段保持空白并在uncertainties说明。未提供可信落地页时显式转化目标不进入规划，认知目标CTA为空。

## 使用顺序

1. 上传一张商品图片并描述场景，生成15秒、三个镜头的脚本；人工检查、修改并确认。也可通过高级入口手工填写需求、卖点、品牌和镜头。确认版本不可变；草稿修改不会改变历史。
2. 确认当前脚本后进入“镜头素材”；历史确认有独立制作入口，每个版本只有一份可编辑制作状态，不迁移其他版本的候选和采用项。
3. 逐镜头选择支持9:16和所需时长的受管视频模型，获取报价。旁白模型、音色和格式来自已安装协议；不支持的选项不猜测、不降级。
4. 为镜头选择1–3个候选，查看冻结请求、参考资源、每项报价上限和有效期；逐项勾选完整批次后点击“确认全部费用并生成”。报价本身不调用模型；刷新不批准，参数变化清除授权勾选。报价过期需重新获取并确认。
5. 对照商品原图播放候选、试听旁白，填写验收理由后明确批准并选用。生成成功不等于采用；当前查看不改变采用项。拒绝已采用候选需明确清除选用。候选保留历史；未知时长、缺文件或类型不符不能采用。新视频采用从0毫秒开始，预览阶段可调整裁剪；旁白不得超出镜头。
6. 可选背景音乐，设定0至1音量并保存。0就是静音；音乐不循环，超长截断，短于全片则结束后静音。默认TTS设置仅影响后续新候选，不重生成或替换既有旁白。
7. 进入“成片预览”，设定裁剪和pad/crop适配，点击“一键生成粗剪”。服务端重新探测真实时长和尺寸，不信任模型标称时长；缺镜头、裁剪不足、旁白超长明确拒绝，不补黑片。已有当前组装和有效输出时复用，不因进入导出阶段再次渲染。
8. 选择“审看此输出”，播放真实MP4、核对来源并填写理由，明确批准此成片；再进入“导出交付”确认同一输出。服务端校验原批准、组装、渲染尝试、文件及当前依赖一致，下载复用该文件。高级时间线为独立编辑分支，不覆盖原组装；时间线示意预览不替代最终MP4混音检查。此段交付实现已通过独立审查，隔离Chrome合成素材流程已通过，最终独立整体复核已通过，用户与目标环境验收仍待完成。

## 保存、重试与费用

- 草稿与制作设置自动串行保存，使用revision比较并交换。页面区分“正在保存”“仅保存在本机”和“已与服务端同步”；本机缓存不代表换设备可恢复。缓存读取完成且结构校验通过后才开放表单；冲突暂停提交，保留本地设置并展示服务端版本，用户决定普通编辑采用哪一份，不能无提示覆盖。
- 候选采用是独立显式写入，不进入普通自动保存草稿。失败后先读取服务端核对；未确认的采用不会随下次音量修改重放。采用响应丢失且读取失败时暂停后续保存，直至重新读取并解决；已选候选以服务端确认值为准。
- 报价、组装与渲染使用客户端操作键。网络失败保留用户scope下的操作键；同一请求重发恢复原记录，已批准报价恢复同一任务。历史任务不原地复活，明确创建新尝试才产生新任务。
- 任务预授权、扣款、退款复用现有账务合同；报价上限约束最终结算。失败与取消不能被晚到成功覆盖。任务保留广告来源标记，删除广告后也不能通过通用重试绕过重新报价批准。渲染为本地FFmpeg任务，不调用收费模型，但占用服务器资源。
- 草稿、确认版本、制作采用、候选、组装和渲染结果均参与资源引用保护。删除广告不删除独立媒体与账务；有关联执行任务时拒绝删除。

## 候选批次与安全恢复

候选批次后端支持每个镜头一次1–3个独立候选。先冻结要求和各成员报价，再显式批准完整镜头批次；批次中的每个候选仍是独立Task与结算，不能把“批量”理解为一次供应商调用。任一成员报价校验失败整批不接纳；任务执行后的部分失败不重跑成功候选。候选比较、人工验收、问题记录与返工建议已接入实际页面，隔离Chrome已验证核心流程，长期离线与全部故障组合仍待目标环境验收。记录问题不会生成任务；返工只预填可修改的建议，必须重新获取报价并授权，不自动解决原问题。

不同操作键也受服务端活动任务保护。除排队/运行外，结果未知、取消未确认、作品待保存与计费待核对都可能继续阻止新尝试；本地失败不代表上游没有生成。网络响应丢失先按原操作键查询。已有作品保存失败只恢复媒体；已知供应商任务ID的失败视频可显式查询并通过相同加密检查点登记；没有可核对ID或协议能力时保留待人工核对，不自动重建。可信查询明确失败或取消时，在原恢复租约下将任务终态诊断与原账单退款一并提交；任一步失败整体回滚，仍保持阻断。网络或解析错误不证明上游失败，重复查询日志也不会覆盖已核对的终态。

## 技术边界

Schema80新增制作、提交、组装、渲染尝试四表，使用仓库原生迁移。TimelineProject v2保留统一tracks/clips及Resource/Asset引用，不另造渲染协议。输出只有成功任务、实测音视频流/尺寸/时长合格且文件当前可读时才显示下载。

视频采用所选视频流时长，而不是容器内较长音轨的时长；视频流时长未知则拒绝组装，不用末帧补足。混音保留固定单片段音量，不随早先旁白或音乐结束而放大后段。

远程探测沿用现有8MiB头部读取和有界超时；非faststart远程媒体可能明确失败，此时应重新上传可探测媒体，而不是跳过探测。Canvas组装匹配素材当前按账号扫描；素材规模导致性能问题时再改索引查询。

## 验收与复现

- 自动检查覆盖原生迁移、报价批准幂等/计费上限、资源引用/删除、候选时长、不可变组装、取消晚到结果、真正的FFmpeg输出。
- 15秒TEST测试图案与正弦音频只证明技术链路：1080×1920、音轨、文字/Logo、各段画面、原视频静音、旁白/音乐结束后的静音。不代表商品一致性或广告质量。
- 真实浏览器测试使用生产构建和只编译于Go测试的隔离服务，未在产品增加假成功入口。

浏览器复现命令：

```bash
cd web
bun run build
env -u ADVERTISING_REAL_PROVIDER_KEY bun scripts/advertising-generation-chrome-e2e.mjs
```

需要Chrome、Go、Bun、FFmpeg/ffprobe和可用字体。脚本建立临时SQLite、TEST本机provider和独立Chrome用户目录，并清理自身进程。截图、日志和标为TEST的MP4在Git忽略的验证目录中。
